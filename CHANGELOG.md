# Журнал изменений

Версии — [semver](https://semver.org/lang/ru/): до 1.0 интерфейс может меняться.

## 0.6.0 — 2026-08-21

- **Подключение перестало выгорать по квоте токенов.** Сервер сохраняет `refresh_token` и продлевает доступ вместо выпуска нового токена. У ВК лимит в 5 активных токенов на приложение и пользователя; раньше срок истекал раз в сутки и каждый раз занимался новый слот, так что через несколько дней клиент упирался в `token_limit_exceeded` и был вынужден отзывать все токены — включая нужные ему для других задач. Теперь подключение занимает один слот постоянно. Проверено на живом API: продление выдаёт рабочий токен и не уменьшает счётчик свободных слотов.
- **Кэш токенов переживает выкладку** — том в `docker-compose.yml`. Без него `refresh_token` терялся при каждом передеплое и всё начиналось заново.
- Ошибка `token_limit_exceeded` дополняется подсказкой, что делать, вместо предложения ВК написать письмо в поддержку.

## 0.5.0 — 2026-07-30

- **Подключение по постоянным данным доступа в адресе.** К форме `/t/<токен>` добавились `/o/<client_id>/<client_secret>` и `/c/<токен click.ru>/<id аккаунта>`. Готовый токен ВК Рекламы живёт всего 24 часа, поэтому адрес с ним приходилось бы обновлять ежедневно; по новым формам сервер выпускает и обновляет токен сам, и адрес достаточно вставить один раз. Ограничения сетевого режима действуют для всех форм одинаково.
- Тесты больше не пишут в настоящий кэш токенов пользователя: временный каталог на каждый прогон.

## 0.4.0 — 2026-07-30

- **Подключение по одному токену.** Для клиентов, которые позволяют указать только адрес сервера и не умеют задавать заголовки (Claude Desktop), добавлен эндпоинт `/t/<токен VK Ads>`: пользователь вставляет адрес с собственным токеном — и всё, ни установки программ, ни отдельного входа. Включается переменной `MCP_ALLOW_URL_TOKEN=true`, по умолчанию выключен. Заголовки, если они присланы, имеют приоритет; обычный `/mcp` по-прежнему требует токен шлюза.
- Согласование версии протокола: сервер отвечает той версией, которую запросил клиент (`2025-06-18`, `2025-03-26`, `2024-11-05`), а не всегда самой старой — раньше новые клиенты получали неожиданный ответ.

## 0.3.0 — 2026-07-30

Исправления по итогам аудита безопасности и поддерживаемости.

- **Изоляция доступа между аккаунтами.** Ключ хранения токена теперь включает отпечаток секрета. Раньше в сетевом режиме клиент, знавший только публичный идентификатор (`client_id` или Click.ru `account_id`), получал из общего кэша токен, выписанный на чужие данные доступа. Ротация секрета также перестала переиспользовать старый токен.
- **Ограничения загрузки креативов в сетевом режиме.** Чтение файлов с диска сервера выключено, адреса для загрузки по ссылке проверяются: внутренние диапазоны и уводящие туда перенаправления блокируются, разрешены только `http` и `https`, размер ответа ограничен. Управление: `VK_ADS_ALLOW_LOCAL_FILES`, `VK_ADS_ALLOW_PRIVATE_NETWORK` (при локальном запуске обе возможности включены, как раньше).
- Проверка токена шлюза выполняется за постоянное время.
- Хранилище токенов вынесено в отдельный модуль, получило вытеснение по сроку и лимиту — раньше кэш в памяти рос без ограничения.
- Версия сервера берётся из `package.json`, а не задаётся строкой в коде.
- Тесты: 54 → 110, добавлено покрытие HTTP-транспорта, хранилища токенов и защиты от подстановки адресов. Типы и тесты запускаются на каждый pull request.

## 0.2.1 — 2026-07-27

- Служебное поле `mcpName` в package.json — связь пакета с записью в официальном реестре MCP.

## 0.2.0 — 2026-07-27

Первый публичный релиз.

- 48 операций в 10 группах: аккаунт и доступ, кампании, группы, объявления, аудитории и сегменты, пиксели, изображения и видео, бюджеты и ставки, статистика, справочники.
- Три режима подключения: через Click.ru (основной; сервер сам получает и обновляет токен ВК), готовый токен ВК Рекламы, OAuth-приложение с target.vk.ru (включая режим агентства от имени клиента).
- Транспорты stdio и HTTP (мультиаккаунт через заголовки).
- Номер версии отражает фактическую зрелость; изменения до 0.2.0 велись без журнала.
